# Common Rule — Collaboration, Shared State, and Ownership

| ID | Requirement | Agent behavior |
|---|---|---|
| COL-01 | Shared conventions | Follow the same repository instructions, terminology, standards, and accepted architectural decisions. |
| COL-02 | Consistent language | Use established names for domain concepts, modules, APIs, events, and components. Avoid creating competing names for the same concept. |
| COL-03 | Decision consistency | Respect accepted ADRs, project constitution, and decisions made for the active feature unless new evidence justifies revisiting them. |
| COL-04 | Clear handoffs | Transfer objective, progress, findings, changed paths, verification, assumptions, and unresolved issues. |
| COL-05 | Duplicate-work prevention | Check current assignments, task status, and repository changes before starting potentially overlapping work. |
| COL-06 | Shared-file awareness | Inspect current file state before modifying shared files; coordinate changes to generated files, migrations, lockfiles, and central configuration. |
| COL-07 | Knowledge preservation | Record material discoveries in the appropriate Spec Kit artifact, ADR, project documentation, or concise handoff. Avoid unrelated scratch files. |
| COL-08 | Conflict resolution | Resolve conflicting findings using requirements, evidence, project rules, and explicit decisions. Escalate unresolved business conflicts. |
| COL-09 | Ownership boundaries | Respect agent role, permissions, task ownership, and file ownership. Do not silently take over another agent's work. |
| COL-10 | Integration responsibility | The primary agent validates that individually completed contributions work together; separate passing subtask checks do not prove end-to-end correctness. |
