# API and Contract Design Skill

- Identify API consumers, ownership, compatibility requirements, and trust boundaries.
- Define request/response or event schemas, validation, error semantics, and examples.
- Use protocol semantics consistently; for HTTP, choose methods and status codes appropriately.
- Enforce server-side authorization and validation.
- Consider versioning, idempotency, pagination, rate limits, and request-size limits where applicable.
- Define timeout, retry, and failure behavior for external integrations.
- Avoid leaking internal stack traces, infrastructure details, or sensitive values.
- Add contract/integration tests and keep API documentation synchronized.
- Consider backwards compatibility and migration plan before changing existing consumers.
