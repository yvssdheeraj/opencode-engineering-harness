# Software Engineering Skill

1. Inspect the existing architecture and conventions before proposing changes.
2. Prefer simple, cohesive modules with clear responsibilities and explicit dependencies.
3. Apply SOLID, DRY, KISS, YAGNI, DDD, and design patterns only where they solve an actual problem.
4. Preserve behavior and public contracts unless the task explicitly changes them.
5. Use strong types/contracts, deliberate error handling, and controlled side effects.
6. Keep changes narrow; avoid speculative abstractions and unrelated refactors.
7. Design for testability and observability.
8. Update relevant tests and documentation.
9. Run repository checks and inspect the final diff.
10. Follow project constitution and technology-specific instructions over generic examples in this skill.
